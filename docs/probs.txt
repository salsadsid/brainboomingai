  Architecture & Engineering Issues
                                                                                                                        
  1. Extreme Copy-Paste Engineering
                                                                                                                        
  Every single tool component (SpellCheckerTool, AiToHumanConverter, PlagiarismCheckerTool, GrammarCheckerTool, etc.) is
   the same 400+ line component copy-pasted with different labels. The form, state management, output rendering,        
  copy-to-clipboard, FAQ sections -- all identical. A 3 YoE dev should know how to extract a shared ToolTemplate        
  component and pass in configuration. This is the single biggest red flag for engineering maturity.

  2. The "Plagiarism Checker" is Fake                                                                                   
  
  PlagiarismCheckerTool.tsx:62 imports free_grammar_checker_prompt -- it literally runs the grammar checker prompt and  
  calls it plagiarism detection. The FAQ claims it "scans billions of web pages" and "academic databases." It does none
  of that. It just sends text to Gemini. This is dishonest to users and would raise serious trust concerns in an        
  interview.      

  3. Redux is Over-Engineered for What It Does                                                                          
  
  You have a full Redux Toolkit setup (store.ts, rootReducer.ts, api.tsx, promptApi.tsx, provider.tsx, hooks.ts)        
  wrapping a single POST endpoint. RTK Query here buys you nothing over a plain fetch call or even a simple custom hook.
   The store also disables both serializableCheck and immutableCheck (store.ts:22-23), which defeats the purpose of     
  using Redux's safety features. This screams "I added Redux to put it on my resume" rather than making a deliberate
  architectural choice.

  4. LangChain for a Single API Call                                                                                    
  
  lib/googleAIService.ts uses LangChain (@langchain/google-genai) to make one .invoke() call. You also have             
  @google/genai installed but seemingly unused. LangChain is a heavy abstraction meant for chains, agents, and complex
  workflows. For a single prompt-response call, the native Google SDK is simpler and lighter. Two competing AI SDKs in  
  package.json looks sloppy.

  5. In-Memory Rate Limiter Won't Work                                                                                  
  
  lib/rateLimit.ts uses a Map in process memory. On Vercel (or any serverless platform), each function invocation can be
   a new cold start. The rate limit map resets between invocations and isn't shared across instances. This provides
  essentially zero protection in production.                                                                            
                  
  6. The App Lies to Users About Data Storage                                                                           
  
  The FAQ on every tool says "Your text is not stored on our servers." But app/api/generate/route.tsx:33-38 explicitly  
  saves every prompt and response to MongoDB via GeneratedResponseModel.create(). This is a real ethical/legal issue,
  not just a code quality concern.

  Code Quality Issues
                     
  7. No Tests -- Zero
                                                                                                                        
  No test files anywhere. No Jest, Vitest, Playwright, Cypress -- nothing. The CI pipeline (ci.yml) runs lint,          
  type-check, and build, but no tests. For 3 YoE, interviewers expect at least basic unit tests for utility functions   
  and integration tests for API routes.                                                                                 
                  
  8. Typo Permanently Baked into URL Structure                                                                          
  
  The directory is free-grammer-checker (should be "grammar"). This means the production URL has a typo. Fixing it later
   means breaking existing links/SEO. This shows lack of attention to detail.
                                                                                                                        
  9. Dead Code Everywhere                                                                                               
  
  - page-new.tsx files exist in multiple tool directories -- abandoned drafts left in the repo                          
  - WordFrequency model (models/WordFrequency.ts) appears unused
  - utils/aiWords.ts, utils/calculateWordFrequency.tsx -- unclear if these are used anywhere                            
  - Commented-out code in prompt.ts files                                                                               
                                                                                                                        
  10. dangerouslySetInnerHTML with AI Output                                                                            
                                                                                                                        
  Every tool component renders AI-generated text via dangerouslySetInnerHTML. You use DOMPurify which helps, but the    
  prompts explicitly ask the AI to return HTML. You're trusting an LLM to generate safe HTML. DOMPurify mitigates this
  but the pattern itself is fragile -- any configuration gap and you have XSS from AI output.                           
                  
  11. Fake Event Hack                                                                                                   
  
  In every tool component:                                                                                              
  await handleSubmit(new Event("submit") as unknown as FormEvent);
  Casting a native Event through unknown to FormEvent is a code smell. Extract the core logic into a separate function  
  that doesn't need a form event.                                                                                     
                                                                                                                        
  12. React Anti-Patterns
                                                                                                                        
  - Using index as key for the outputs list (outputs.map((output, index)) -- React docs explicitly warn against this for
   dynamic lists                                                                                                        
  - Zod schema is recreated on every render (defined in component body, not module scope)                               
  - Toaster component is rendered both in the root layout.tsx AND inside individual tool components -- duplicate toast  
  containers
